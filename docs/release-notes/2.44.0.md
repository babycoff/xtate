# Xtate 2.44.0 release notes

Released 2026-11-13.

## Highlights

### Browser GUI for the control plane

Xtate gains a local browser dashboard for managed jobs:

```bash
xtate --control-plane=/tmp/xtate-ctl.sock
# in another terminal, with the same XTATE_CONTROL_TOKEN if one is set:
xtate --gui --control-connect=/tmp/xtate-ctl.sock
```

The GUI is another control-plane client; it never scans in-process. It lists
jobs, refreshes every three seconds, shows state counters, stderr tail and the
result manifest, cancels jobs with confirmation, and starts a small authorized
scan through a wizard (module, targets, ports, rate, timeout, result path and
optional interface).

The page is embedded into the binary and served by a tiny HTTP server that binds
`127.0.0.1` only. Each run generates a new 128-bit session token, injected into
the page and required in every API request. The server validates the `Host`
header against loopback (DNS-rebinding defence), applies a Content-Security
Policy, and forwards only `job.list`, `job.status`, `job.cancel`,
`job.result_manifest` and `job.start`. `job.start` additionally requires
`params.authorized: true` on the server side.

Use `--gui-listen=127.0.0.1:PORT` to choose a port (`:0` for an ephemeral port)
and `--gui-no-open` to skip opening a browser. The GUI needs a running control
plane; it never starts one itself.

The wizard deliberately covers a subset of `start_scan`: no `include_file`, no
`probe_args`/`scan_args`, no zstd and no quota settings. Use MCP or a scan-request
file for those.

## Compatibility

- No existing CLI, MCP or control-plane request changes.
- The GUI adds `--gui`, `--gui-listen` and `--gui-no-open`; `--gui` requires
  `--control-connect` and never starts a control plane.
- Version strings, `--version` and MCP `serverInfo.version` report `2.44.0`.

## Known limitations

- The GUI is local-only, binds loopback and has no TLS. Do not expose the port.
- The GUI start wizard does not expose the full scan-request surface (see above).
- The GUI does not stream result records; it shows the manifest and leaves chunk
  reading to the scanner CLI, MCP resources or a custom reader.
- On hosts with several default interfaces the worker can fail with `multiple
  default interfaces detected`; run `xtate --explain-target=<target>` and paste
  the reported interface into the wizard.
- Some VPN adapters expose link type `RAW`, which Xtate cannot use for raw scans;
  preflight the target and choose a supported capture interface.
- Cancellation is best-effort; a worker that already exited reports
  `"cancelled": false`.
- The control token is optional for local control transports. Set
  `XTATE_CONTROL_TOKEN` when other local users can reach the socket or pipe.
- MCP still exposes static `targets`/`include_file` only; generate/stream input
  is not exposed through MCP.

## Upgrade notes

No migration is required. Existing control-plane, job, MCP and result files remain
compatible. GUI result paths are interpreted by the control-plane process, not by
the GUI process.
