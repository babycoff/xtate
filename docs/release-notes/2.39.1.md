# Xtate 2.39.1

Fixes the remaining server-first TLS composition gap.

## Fix

- `tls-state` now continues from `TSP_STATE_SAY_HELLO` into `TSP_STATE_RECV_DATA`
  when a state sub-probe has no client hello, allowing already-buffered
  server-first application data to be read.
- MySQL state gains `--after-tls`; it sends a COM_PING wake-up so the MySQL
  greeting is delivered inside TLS.
- ManageSieve state gains `--after-tls`; it sends NOOP so the capability
  greeting is delivered inside TLS.
- TLS composition matrix now hard-asserts:

```text
mysql_version: "8.0.34"
sieve_starttls: true
```

in addition to TLS version, ALPN and certificate subject.

## Tests

- `tests/lab/ci-tls-composition.sh`: implicit MySQL and ManageSieve STARTTLS
  hard assertions.
- Matrix targets are per-connection threaded to avoid stale handshakes blocking
  later cases.

## Verification

```text
nightly: TLS/STARTTLS composition success
Linux build/selftest: PASS
i18n: PASS
```

## Caveat

`mysql-state --after-tls` and `managesieve-state --after-tls` are lab/compatibility
wake-ups, not standard handshakes. MySQL sends a COM_PING before authentication;
strict servers may reject it. ManageSieve sends NOOP before the capability greeting.
Use them only for the TLS composition lab, not as a production guarantee.
