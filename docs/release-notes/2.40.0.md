# Xtate 2.40.0

Adds SSH KEX host-key fingerprinting, DNSSEC evidence probing, and a
route-aware network diagnostics layer.

## SSH

- New `ssh-kex` state probe performs an unauthenticated
  `curve25519-sha256` key exchange and reports:

```text
ssh_host_key_type
ssh_host_key_bits
ssh_host_key_sha256
```

- No user authentication, session, or command execution.
- Verified against `ssh-keyscan`/`ssh-keygen` on a local OpenSSH-compatible
  target.

## DNS

- `dns --dnssec` sends an EDNS0 OPT record with DO=1 and reports:

```text
dns_ad
dns_truncated
dns_rrsig_count
dns_dnskey_count
dns_ds_count
dns_nsec_count
dns_dnssec_present
```

- This is deployment-evidence probing, not DNSSEC chain validation.
- `--edns-size` controls the advertised UDP payload size (default 1232).

## Network diagnostics

- `--list-if` now prints one aligned row per adapter with IPv4, MAC, default
  gateway and state (`up`/`virtual`/`loopback`/`no-ipv4`).
- `--explain-target <ip>` is a read-only target/interface/source/gateway
  summary; `--check` performs a preflight check.
- Windows gateway MAC resolution tries `SendARP` (OS neighbor table) before
  raw ARP.
- Target route lookup: Windows `GetBestInterfaceEx` + IPv6 forwarding table;
  Linux rtnetlink `RTM_GETROUTE`.
- `-if` accepts an index, a GUID, or a unique description substring.
- When several default interfaces exist and `-if` is omitted, startup fails
  closed instead of guessing.

## Caveats

- Windows IPv6 route/source/next-hop are verified; the IPv6 data plane still
  requires a lab target.
- `--explain-target` on Windows reports `Gateway: unknown` for on-link routes.
- The input/output module audit is planned, not part of this release.
