# Xtate 2.35.1

Patch release focused on encrypted-protocol correctness and test depth.

## HTTP/3 QPACK fix

`http3-state` now decodes QPACK **Literal Field Line with Literal Name**
correctly. The QPACK layout is:

```text
001 N H NameLen(3+)
```

`H` is `0x08`; `N` is `0x10`. The previous code checked the `N` bit as the
Huffman bit, so a literal header name produced garbled output such as
`�|���` instead of `x-extra`.

This release also adds a QPACK Huffman frame fixture to `h3_frame_selftest()`,
so the H-bit and Huffman-literal paths are covered without QUIC/TLS.

## Test depth

- TLS/H2: status 404, empty DATA, extra header, multiple HEADERS, matcher,
  certificate subject, TLS version and ALPN `h2`.
- H2C: `--all-frames`, `--settings-hex`, `--ping-hex`, `--no-ping`,
  `--no-settings`.
- HTTP/3: body/header/no-match matching, status 404, empty body, extra header.
- UDP: IPv4/IPv6 echo and ICMP/ICMPv6 port unreachable.
- HTTP-state: all-banner and matching.
- H2C synthetic pcap matrix remains stable.

## Nightly reliability

The encrypted-protocol nightly workflow now:

- fixes H2 source-IP extraction;
- uses the certificate paths expected by the H2 target;
- matches the quoted `h2_status: "200"` field;
- preserves and uploads failure logs;
- adds scan timeouts and target-readiness checks;
- caches the local target image with `docker/build-push-action`.

## Known limitations

- H2C pcap tests do not cover settings/ping because those change the client
  payload length and require per-configuration ZBanner ACK fixtures; settings/ping
  are covered by the live H2C depth script instead.
- TLS/QUIC pcap replay remains intentionally unsupported.
- Dynamic QPACK, HTTP/3 push/CONNECT/WebTransport and Windows quic-state remain
  unchanged roadmap items.
