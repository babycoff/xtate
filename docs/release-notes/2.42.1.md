# Xtate 2.42.1

## Highlights

- **Agent Skill for MCP clients.** A reviewed playbook at `skills/xtate/` teaches
  external agents to confirm scope, preflight routes, validate a closed scan
  request, start a bounded job, and read manifests/chunks. It is documentation
  and policy, not an embedded agent or a privilege boundary.
- **Full-tree audit hardening.** Memory-safety and robustness fixes across DNS,
  NDP/ARP, HPACK, Lua TCP probes, ICMP quote parsing, pcap output, MongoDB output
  and result storage.
- **Windows UTF-8 paths.** CLI argv, include files, job/result paths, output
  files and MCP result paths now use wide-character Windows APIs, so Chinese and
  other non-ASCII paths work instead of being decoded as ANSI.
- **Windows route lookup.** Adapter GUID matching now handles the ANSI adapter
  name correctly; the previous wide-character conversion produced invalid GUIDs,
  so `explain_target`/`check` and MCP planning could fall back to the default
  interface instead of the routed pcap device.
- **Control-plane hardening.** Strict integer parsing, unique request/result
  names, newline-framed Windows Named Pipe I/O, private Unix socket permissions,
  `mkstemp` request files, SIGPIPE handling and maintenance-thread shutdown.
- **Result-store correctness.** Manifest and index paths are JSON-escaped, so
  Windows backslash paths and paths containing quotes produce valid JSON.
- **JSON contract alignment.** `dry_run` now documents its real default
  (`false`), `rate` accepts 0-10000, `chunk_size` requires at least 1, and
  `compression` is `none` or `zstd`. The reference CLI adapter handles
  `include_file`.

## Upgrade notes

- Omitting `dry_run` has always meant a real scan. The schema now says so; tools
  that read the old `"default": true` must set `dry_run: true` explicitly when
  they only want target listing.
- `timeout_sec` must be an integer in 1-86400; negative or non-integer values are
  rejected instead of wrapping.
- Result manifests written by older builds with unescaped backslashes may need
  re-reading with the fixed build; new manifests are valid JSON.

## Verification

Windows regression: selftest, i18n parity/coverage, MCP protocol and stability
suites, generate/input tests, control-plane tests, scan-request runtime tests,
schema and module validators. Linux regression: selftest, i18n, MCP protocol and
stability, generate, control-plane and scan-request runtime suites (the Linux
test image does not ship `jsonschema`, so schema validators ran on Windows).
The audit pass also ran clang ASan and libFuzzer harnesses over preprocessing,
HPACK and DNS parsers.

## Known limitations

- The control-plane token remains optional for local clients; set
  `XTATE_CONTROL_TOKEN` in production. The Unix socket is mode 0600 when created.
- The MCP audit log is written to the MCP process working directory.
- Some VPN adapters present a RAW link type that Xtate cannot use for raw scans;
  preflight with `explain_target` and choose a supported interface or route.
- `include_file` route discovery is not implemented; pass a verified `interface`
  only after preflighting representative targets.
- MCP generate/stream input is still not exposed; use static `targets` or
  `include_file`.
