# Xtate 2.44.1 release notes

Released 2026-11-13.

## Highlights

### One-command local TUI and GUI

Starting a local TUI or GUI no longer requires a second terminal and a separate
`--control-plane` process:

```bash
xtate --tui
xtate --gui
```

When `--control-connect` is omitted, the UI starts a private control plane in a
child process, waits until it accepts `ping`, and stops it when the UI exits. The
private child inherits `XTATE_CONTROL_TOKEN` from the UI process, so token
enforcement still applies when a token is set.

`--control-connect` remains available for attaching to an existing control plane,
which is the right choice when jobs must outlive the dashboard:

```bash
xtate --control-plane=/tmp/xtate-ctl.sock
xtate --gui --control-connect=/tmp/xtate-ctl.sock
```

In private mode the control plane owns the workers and is stopped with the UI;
running or queued jobs therefore stop too. Use `--control-connect` for long-lived
jobs.

The auto-start path uses the same executable and control-plane protocol; it does
not embed a scanner in the TUI/GUI process. On Windows the child is placed in a
kill-on-close job object; on Linux it receives `PR_SET_PDEATHSIG` and is stopped
with SIGTERM/SIGKILL. Readiness is a `ping` retry loop, not a fixed sleep.

### Documentation

- TUI and GUI guides (English and Chinese) now show the one-command form first and
  document private-mode lifetime, token inheritance and when to attach an
  existing daemon.
- Root READMEs and troubleshooting tables were updated.

## Compatibility

- No existing CLI, MCP or control-plane request changes.
- `--tui` and `--gui` without `--control-connect` now succeed by starting a private
  control plane instead of printing a `requires --control-connect` error.
- Version strings, `--version` and MCP `serverInfo.version` report `2.44.1`.

## Known limitations

- In private mode, stopping the TUI/GUI stops its control plane and its jobs. Use
  `--control-connect` for jobs that must continue independently.
- The private control plane is local-only: a Windows Named Pipe or Unix domain
  socket in the user's temporary directory; no TCP listener is opened.
- The GUI remains loopback-only and has no TLS. Do not expose its port.
- The GUI start wizard still covers a subset of `start_scan` (no `include_file`,
  `probe_args`/`scan_args`, zstd or quota settings).
- Cancellation is best-effort; a worker that already exited reports
  `"cancelled": false`.
- The control token is optional for local control transports. Set
  `XTATE_CONTROL_TOKEN` when other local users can reach the socket or pipe.
- MCP still exposes static `targets`/`include_file` only; generate/stream input
  is not exposed through MCP.

## Upgrade notes

No migration is required. Existing control-plane, job, MCP and result files remain
compatible. Scripts that relied on `--tui`/`--gui` failing without
`--control-connect` should pass an explicit endpoint if they need the old
two-process behaviour.
