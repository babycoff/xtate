# Xtate 3.0.0

Xtate 3.0.0 is the first stable release of the 3.0 line. It keeps the scanner
engine and result format of 2.44.x, and adds a scan-first browser console, a
typed MCP server for AI hosts, an Agent Skill for safe MCP use, a bilingual
manual, explicit protocol capability reporting, and a reproducible Linux Docker
image.

The command line remains the primary interface for expert Internet measurement
and research. The GUI and MCP server are additional clients over the same
engine and control plane; they do not replace the CLI.

## Highlights

- **Scan-first browser console.** New scan, live job view, results, interfaces,
  modules and system pages; server-side preflight; managed per-run result
  directories; English and Chinese UI; loopback by default with an explicit
  remote-access opt-in.
- **MCP server.** Fourteen typed tools over a private control plane: discovery,
  route checks, preflight, config validation, managed scan jobs, bounded result
  reads and cancellation. No shell, no inline result dumps, no TCP listener.
- **Agent Skill.** `skills/xtate/` teaches an external agent to use the MCP
  server safely. It is MCP-only guidance, not a security boundary.
- **CLI.** Stable scan/probe/output/generate module model, route-aware
  `--explain-target`/`--check`, job-aware control-plane client, offline and
  reproducible target input, and the interactive console.
- **Protocols.** HTTP/1.1 and HTTP/2 state probes; HTTP/3 and QUIC transport on
  Linux; TLS composition, STARTTLS, DNS/DoT/DoH, SSH KEX, mail, database and
  industrial protocol probes; Windows explicitly reports HTTP/3/QUIC as
  unavailable.
- **Measurement operations.** JSON/NDJSON output, chunked results, zstd
  (build-dependent), quotas, retention, flow control, and a documented
  Ubuntu 24.04 Docker image with all optional dependencies.

## Defaults and rate handling

The default scan rate is **100 packets per second** on every surface.

Xtate itself accepts positive fractional and very high rates. For example,
`-rate 0.5` sends one packet every two seconds, and `-rate 1000000` is valid for
high-rate measurement on suitable hardware and paths. The browser GUI limits the
rate field to 1–10,000 for UI stability: this is a GUI safety limit, not an
engine limit. Expert high-rate work belongs on the command line, MCP or the
control plane, where no artificial cap is applied.

The interactive console validates `set rate` immediately but does not impose an
upper bound. It adds `check`, structured `set-subprobe`/`set-subprobe-arg`
commands, `history clear`, and scan/probe compatibility warnings. On Windows,
the console explains that it cannot restart itself after a scan; start
`xtate -interactive` again.

## Results and control plane

- Results are chunked NDJSON plus a manifest; clients read bounded pages rather
  than loading a whole file.
- Jobs have explicit lifecycle states, heartbeat, stall detection, timeout and
  cancellation.
- The control plane is local-only: Unix socket on Linux, Named Pipe on Windows.
  Set `XTATE_CONTROL_TOKEN` when sharing an endpoint between processes.
- MCP never exposes a network listener. Common stdio host configurations for
  Claude Desktop, Cursor and VS Code are documented in
  [MCP server](../mcp-server.md).

## Compatibility and upgrades

- Existing 2.44.x result files, target files and configuration keys remain
  readable.
- The 3.0 surface replaces the old TUI with the browser console; scripts that
  used `--tui` should move to `--gui`. The TUI is retained only as a deprecated
  legacy client and is not part of the 3.0 manual.
- New global parameters and module parameters are additive. See
  [Migrating to 3.0](../migration-3.0.md) for the full checklist.
- The GUI is local by default. Binding it to a non-loopback address requires
  `XTATE_GUI_ALLOW_REMOTE=1`; the Host header is validated and the session token
  is still required.

- Windows full regression: version/surface consistency, schema and module

  EN/ZH chapter parity checked.

## Known limitations

- Windows does not provide HTTP/3 or QUIC transport. The capability report says
  so explicitly.
- Raw L2 scans need a capture interface with a supported link type; Linux
  `loopback` has no Ethernet MAC. Use an on-link target and the real capture
  interface.
- Linux banner/state scans require the documented firewall/RST-suppression
  rules for the duration of the scan.
- The Linux archive links distribution libraries; the Docker image is the
  self-contained option. The Ubuntu 24.04 runtime packages are:

  ```bash
  sudo apt install libssl3 libpcre2-8-0 libxml2 libbson-1.0-0 \
    libmongoc-1.0-0 zlib1g libzstd1 libngtcp2-9 \
    libngtcp2-crypto-gnutls2 libgnutls30t64 libpcap0.8
  ```

- High-rate numbers depend on the adapter, driver and path. The documented
  large-scale rates are operating guidance, not guarantees.
