# Xtate 2.43.0 release notes

Released 2026-11-13.

## Highlights

### TUI control-plane dashboard

Xtate gains a full-screen terminal dashboard for managed jobs:

```bash
xtate --control-plane=/tmp/xtate-ctl.sock
xtate --tui --control-connect=/tmp/xtate-ctl.sock
```

The TUI is a control-plane client, not a second scanning path. It lists jobs,
refreshes every two seconds, shows status details and the result manifest, cancels
jobs with confirmation, and starts a small authorized scan through a wizard
(module, targets, ports, rate, timeout, result path, optional interface, exact
`YES` confirmation). `j/k` or arrow keys select, `r` refreshes, `s` starts,
`c` cancels, `Enter` opens details, and `q` restores the terminal.

When stdin or stdout is not a terminal, `--tui` prints one plain-text snapshot
instead. This is used by the smoke tests and works on Windows Named Pipes and
Unix sockets.

The wizard deliberately covers a subset of `start_scan`: no `include_file`, no
`probe_args`/`scan_args`, no zstd and no quota settings. Use MCP or a scan-request
file for those. The control plane remains local-only and the token remains
optional for local sockets/Pipes; set `XTATE_CONTROL_TOKEN` on shared machines.

## Compatibility

- No existing CLI, MCP or control-plane request changes.
- The TUI adds the `--tui` flag; it requires `--control-connect` and never starts
  a control plane itself.
- Version strings, `--version` and MCP `serverInfo.version` report `2.43.0`.

## Known limitations

- The TUI is local-only and does not stream result records; it shows the manifest
  and leaves chunk reading to the scanner CLI, MCP resources or a custom reader.
- The TUI start wizard does not expose the full scan-request surface (see above).
- On hosts with several default interfaces the worker can fail with `multiple
  default interfaces detected`; run `xtate --explain-target=<target>` and paste
  the reported interface into the wizard.
- Some VPN adapters expose link type `RAW`, which Xtate cannot use for raw scans;
  preflight the target and choose a supported capture interface.
- Cancellation is best-effort; a worker that already exited reports
  `"cancelled": false`.
- The control token is optional for local control transports. Set
  `XTATE_CONTROL_TOKEN` when other local users can reach the socket or pipe.
- MCP still exposes static `targets`/`include_file` only; generate/stream input
  is not exposed through MCP.

## Upgrade notes

No migration is required. Existing control-plane, job, MCP and result files remain
compatible. TUI result paths are interpreted by the control-plane process, not by
the TUI process.
