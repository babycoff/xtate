# Xtate 2.41.2

JSON contract and error-handling hardening.

## Scan requests

- `xtate --scan-request=request.json` parses the closed JSON request in C and
  runs it without a shell or subprocess.
- Targets are validated as IP/range before the CLI parser; invalid targets
  return `TARGET_INVALID`.
- Missing Linux RST/ICMP rules abort a scan-request with
  `FIREWALL_RULES_MISSING`.
- `dry_run` maps to target listing and sends no packets.

## Error codes

- Added `error-code.h` and frozen the error catalog in
  `schemas/error-codes.json`.
- `--scan-request` errors are emitted as JSON envelopes:
  `{"error":{"code":"...","message":"...","retryable":...}}`.
- `PERMISSION_DENIED`, `OUTPUT_WRITE_FAILED` and `FIREWALL_RULES_MISSING`
  are used by real paths.

## Output

- All file output modules use `out_fprintf`/`out_fputc`/`out_fwrite`.
- Write, flush and close failures set `OUTPUT_WRITE_FAILED`, mark output fatal
  and exit non-zero. MongoDB uses `mongo_fail()`.
- End-to-end test: `tests/schema/test_output_failure.sh`.

## UX

- Selecting an output module without `--show` prints a hint; `--show all` is
  supported.
- `--list-modules-json` emits module metadata for JSON-contract validation.
