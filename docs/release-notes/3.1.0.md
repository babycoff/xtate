# Xtate 3.1.0

Xtate 3.1.0 is a minor release on top of the stable 3.0 line. It makes the
stateful-probe transport model explicit, exposes that model through every
interface, allows `close-state` to stop QUIC handshakes, and cleans up the
bilingual GUI and container interface enumeration.

The command line remains the primary interface for expert Internet measurement
and research. The GUI, MCP server and Agent Skill are additional clients over
the same scan engine and control plane.

## Highlights

- **Probe transport is now a first-class property.** Stateful probes declare
  `ProbeTransport` (`TCP`, `QUIC`) and optional `ProbeCapability`
  (`stream-data`). Scan modules declare the transport and capability they
  require. `tcp-state` accepts TCP state probes; `quic-state` accepts QUIC
  state probes.
- **`close-state` works on QUIC.** `close-state` sends no application request
  and closes the transport after the handshake. It is now accepted by
  `tcp-state`, `tls-state` and `quic-state`; `http3-state` remains the QUIC
  `stream-data` probe that sends an HTTP/3 request.
- **Module metadata is discoverable.** `--list-scan` and `--list-probe` print
  type, state transport and capability metadata; `--help-scan` and
  `--help-probe` explain the accepted probe shape. The GUI Modules page shows
  transport and `stream-data` badges, and MCP `list_modules`/`describe_probe`
  and the Agent Skill describe the same fields.
- **Compatibility is enforced consistently.** CLI, interactive mode, GUI
  preflight, MCP `validate_config` and `start_scan` all use the same
  compatibility helper. Invalid combinations such as `quic-state + http-state`
  or `tcp-state + http3-state` are rejected before any packet is sent.
- **GUI and container polish.** The Chinese System page and English New scan
  page no longer leak the other language; dynamic status text is localized.
  Libpcap pseudo-interfaces (`any`, `nflog`, `nfqueue`, `dbus-*`, ...) are
  filtered from GUI interface enumeration, removing repeated `No such device`
  log noise in containers.

## Probe model in one minute

| Concept | Meaning |
|---|---|
| Probe type | The module ABI: `tcp`, `udp`, `state`. |
| State transport | The wire context a state probe can run in: `TCP`, `QUIC`, or both. |
| `stream-data` | The probe consumes decrypted application bytes after the handshake. |

`http3-state` is `state` + `QUIC` + `stream-data`. `tls-state` is `state` +
`TCP`. `close-state` is `state` + `TCP/QUIC` with no `stream-data` because it
stops at the handshake. A future probe may declare both transports; the model
does not assume that every state probe is TCP-only.

## Compatibility and upgrades

- Upgrading from 3.0.0 requires no scan-configuration, result-file or MCP
  request-shape changes.
- `quic-state + close-state` is newly accepted. `quic-state + http3-state`
  remains the normal HTTP/3 pair; `quic-state + http-state` is rejected.
- Module JSON gains `state_transports`, `capabilities`,
  `required_state_transports` and `required_capabilities`. Consumers should
  ignore unknown optional fields.
- The human-readable `--list-scan`/`--list-probe` output now adds an indented
  metadata line after each module name. Scripts that parse the name line by
  column should skip or tolerate the following metadata line.
- The `v3.0.0` tag is unchanged. 3.1.0 is a normal upgrade from it.

## Known limitations

- Windows does not provide HTTP/3 or QUIC transport; the capability report says
  so explicitly.
- Raw L2 scans need a capture interface with a supported link type; Linux
  `loopback` has no Ethernet MAC. Use an on-link target and the real capture
  interface.
- Linux banner/state scans require the documented firewall/RST-suppression
  rules for the duration of the scan.
- The Linux archive links distribution libraries; the Docker image is the
  self-contained option. See [Docker build](../docker-build.md) for the
  documented Ubuntu 24.04 runtime packages.
- High-rate numbers depend on the adapter, driver and path. The GUI caps the
  rate field at 1–10,000 for UI stability; this is not an engine limit. The CLI,
  MCP and control plane accept positive fractional and very high rates.
