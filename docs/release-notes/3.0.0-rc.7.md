# Xtate 3.0.0-rc.7

**Release candidate — for hands-on trial, not the final 3.0.0.**

This candidate prepares the 3.0 release: CI integration, binary assets with
checksums, a real MCP/Agent Skill acceptance pass, help/documentation fixes,
version consistency checks and a 2.44.x migration guide.

## Release engineering

- CI now runs the MCP contract, Agent Skill contract, GUI, control-plane,
  scan-request, generate and schema/module checks on Linux, plus the same
  contract checks on Windows.
- A Docker CI job builds the Ubuntu 24.04 full-feature image, asserts
  `raw_sockets`, `http3`, `quic_transport` and `zstd`, and exercises the host
  GUI page and preflight.
- A tag workflow builds Linux and Windows assets and attaches them to the
  GitHub Release, with `SHA256SUMS` and `BUILD-INFO`.
- `scripts/package-release.ps1` and `scripts/package-release.sh` package binaries,
  DLLs, docs, schemas, skills and `SHA256SUMS`; both produced the rc.7 assets
  listed with this release.
- `tests/release/test_version_consistency.py` checks CMake, `version.h`, the
  binary, MCP `serverInfo.version` and version banners in the docs.

## MCP and Agent Skill

- Flat `start_scan`, unknown-field rejection, 8 KiB overflow diagnostics,
  array/string `preflight`, real `check`, JSON-escaped control tokens and
  `global_args` validation are covered by the contract suite.
- Independent acceptance reports 15 passing checks; the five job-lifecycle
  checks remain blocked in the sandbox by named-pipe access. The product test
  suite exercises the full lifecycle on Windows and Linux.

## GUI and control plane

- The GUI page is no longer served without authentication. The printed URL
  carries a one-time bootstrap token, sets an HttpOnly SameSite cookie and the
  API also accepts the per-session header.
- The GUI strips a browser-supplied `result_path`; all GUI scans use the
  server-managed `runs/<timestamp>-<seq>/` directory.
- Control-plane method dispatch is exact (no substring matching) and Unix
  clients have 30-second socket timeouts.
- GUI opens log/result files directly with Notepad instead of waiting on
  ShellExecute/DDE; it never launches a browser.

## Help and documentation

- Long help lines wrap at the last space instead of mid-word, and option names
  are no longer split.
- Fixed `--exclude-ranges` registration, `--tx-thread-count` default, source-port
  range, usage names, separators and several help typos.
- Added `docs/migration-3.0.md` and the Chinese translation, covering flat
  MCP requests, managed result paths, TUI deprecation, no browser auto-open,
  Linux-only HTTP/3/QUIC and rollback.
- Refreshed README module counts, tool list, optional dependency explanations
  and the Chinese module reference.

## Compatibility

- No result-format change.
- The nested `start_scan` form remains rejected; use flat scan-request fields.
- GUI scans always use managed run folders; a browser cannot choose a result
  path.
- TUI remains deprecated and is not part of 3.0.

## Verification

- Windows MSVC Release build and full suite: pass.
- Linux Ubuntu 24.04 build and full suite: pass.
- Docker image build, capability assertions, host GUI and MCP stdio: pass.
- Release assets and checksums: produced and inspected.
- Documentation relative links: checked.

## Known limitations

- A sandbox without named-pipe access cannot exercise the full MCP job
  lifecycle; that case is reported as blocked, not passed.
- `preflight` does not support `include_file`.
- The Docker image cannot open a file picker or the host's result viewer; use
  the mounted `/data` path or the GUI Results page.
- Final 3.0.0 remains gated on user trial and sign-off.
