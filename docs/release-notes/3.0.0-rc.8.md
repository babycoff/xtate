# Xtate 3.0.0-rc.8

**Release candidate — for hands-on trial, not the final 3.0.0.**

This candidate is the release-engineering follow-up to rc.7. It fixes the CI
failures found after rc.7 was tagged, makes every hosted CI matrix green, and
republishes the Windows/Linux assets from the verified commit.

## Changes since rc.7

- CI is green across Linux gcc/clang release and debug, ASan+UBSan, clang
  libFuzzer smoke, the MCP/Skill/GUI/control integration job, the Docker image
  job, and all four Windows jobs (MSVC, clang-cl, MinGW UCRT64 and MINGW64).
- MinGW portability: OpenSSL-dependent probes are omitted consistently when
  OpenSSL is disabled, random bytes use a portable helper (OpenSSL,
  BCryptGenRandom or /dev/urandom), and the logger includes its libc header.
- ngtcp2 compatibility: builds where the library exposes BBR v2 as
  `NGTCP2_CC_ALGO_BBR` no longer fail on the removed `BBR2` enum.
- Preflight no longer fails when link-type inspection needs
  CAP_NET_RAW; it returns an explicit warning and lets scan startup perform the
  authoritative check.
- The libFuzzer target-parser harnesses link the file-open helper introduced by
  the Windows UTF-8 work.

The rc.7 feature set is unchanged: scan-first console, English/Chinese UI,
Xtate module taxonomy with expandable detail, 23 validated global parameters,
per-run result folders, managed state, one-command GUI/MCP, MCP contract
hardening, Docker build environment, checksummed assets and migration guide.
