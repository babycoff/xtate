# Xtate 2.40.1

Hardens input/output handling after the 2.40.0 release.

## Output correctness

- NDJSON strings are JSON-escaped (quotes, backslashes, control characters).
- CSV is RFC4180-style: every field is quoted, embedded quotes are doubled,
  and report columns are valid JSON inside their CSV field.
- CSV append no longer repeats the header.
- BSON output checks UTF-8/date/int32/int64/double/bool/binary append results.
- text/CSV/NDJSON/BSON report `fflush`/`fclose` failures.
- BSON output checks allocation and short writes.

## Input hardening

- BSON input rejects documents larger than 16 MiB and checks allocation.
- `--parse-bson` returns non-zero on malformed input.
- Target files reject lines longer than 65535 bytes instead of splitting them.
- Target files report read errors.
- Overlong `--output-file` paths are rejected instead of silently truncated.
- Mongo BSON import counts insert failures and bulk failures.

## Tests

- `tests/io/audit.sh`: NDJSON/CSV parsing, quoted/backslash fixture, BSON cap,
  target line cap.
- `tests/fuzz/json_escape_fuzz.c`: shared JSON escaping fuzz.
- `tests/fuzz/bson_doc_fuzz.c`: libbson document parser fuzz.

## Known limits

- CSV control characters are covered by the escaping fuzz, not an end-to-end
  pcap fixture (the HTTP parser rejects raw control bytes).
- BSON fuzz covers libbson document parsing, not Xtate BSON file framing/output.
