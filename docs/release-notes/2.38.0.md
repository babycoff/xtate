# Xtate 2.38.0

Adds TLS/STARTTLS composition for the Batch B state probes and the first
Batch C protocols.

## New

- `--after-tls` on `smtp-state`, `imap-state`, `pop3-state`, `ftp-state` and
  `postgres-state`, for composition inside `tls-state` (implicit TLS or
  STARTTLS).
- `mongodb-state` for implicit-TLS MongoDB composition.
- `ipp` / `ipp-state`: unauthenticated IPP Get-Printer-Attributes.
- `amqp` / `amqp-state`: AMQP 0-9-1 protocol header/Connection.Start.
- `pptp` / `pptp-state`: PPTP Start-Control-Connection-Request/Reply.
- TLS/STARTTLS composition lab and Batch C protocol lab.

## Critical documentation fix

The TLS composition lab initially failed because its scanner container did not
run `firewall/add_rules.sh`. This is the same class of mistake users make: the
kernel RSTs raw HLTCP/TLS flows and the scanner prints `open` with no
banner/TLS/probe output.

The firewall prerequisite is now called out explicitly in:

- README and README.zh-CN;
- getting-started (banner and stateful scans);
- troubleshooting (checked first);
- HLTCP;
- known-limitations;
- testing and lab README.

It covers `zbanner`, `tcp-state`, `tls-state`, HTTP/2/HTTP3 and every state
sub-probe, not only ZBanner.
