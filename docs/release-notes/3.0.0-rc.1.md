# Xtate 3.0.0-rc.1

This is a release candidate, not the final 3.0.0. It is published for hands-on
trial and feedback. The final 3.0.0 will follow only after the candidate has
been tested in real use and the reported issues have been fixed.

## Highlights

### A scan-first browser console

The old job-table GUI has been replaced by a task-oriented console:

- **New scan** is the default page: scope, method, ports/probe, rate, timeout,
  interface, authorization, and a live server-side preflight.
- **Live** shows the selected job's phase, sent/targets counters, heartbeat,
  elapsed time, exit code, log path, and manifest.
- **Results** lists completed and running jobs and opens their live view.
- **Interfaces** shows every capture device with addresses, gateway, default
  route, link type, and whether raw IP capture is usable.
- **Modules** lists scan engines, probes, output writers, and generators with
  their parameter names.
- **Settings** shows the runtime endpoint, module counts, and protocol
  capabilities.

`xtate --gui` now starts a private control plane automatically, opens the
browser at `127.0.0.1:8787`, and stops the private worker when the GUI exits.
Use `--control-connect` to attach to an existing daemon instead.

### Server-side preflight

`POST /api/preflight` parses the scope, resolves the route, checks the link
type, validates the selected scan/probe pair, filters ports by the scan
engine's protocol, and returns target/port/attempt counts plus actionable
errors. The page will not enable **Start scan** until preflight passes, the
authorization box is checked, and the form has not changed since the check.

### AI and MCP

- `xtate --mcp` now starts a private control plane automatically, so an MCP
  client can launch the server with one command.
- A new `capabilities` MCP tool reports platform, module counts, raw-socket
  support, and HTTP/3/QUIC availability.
- A new `preflight` MCP tool runs the same packet-free scope/route/link/module
  checks as the GUI, before a scan request is submitted.
- `xtate --list-capabilities` prints the capability document as JSON for agents
  and scripts.

### Protocol capability reporting

HTTP/3 and QUIC transport are built only where ngtcp2 and GnuTLS are
available. On Windows this build reports them as unavailable instead of
silently omitting the modules; the GUI and MCP capability output make the
limitation explicit. HTTP/1.1, HTTP/2, DNS/DoT/DoH, and the stateful TCP/TLS
paths remain available on both platforms.

### Documentation

A structured English/Chinese manual is included under `docs/manual/` and
`docs/zh-CN/manual/` (10 chapters each), alongside the existing reference
chapters. The TUI is
deprecated for 3.0: `--tui` remains in this candidate for compatibility but is
not part of the supported 3.0 interface.

## Verification

- Windows build: MSVC Release, 1,039,360-byte `xtate.exe`, `--version`
  `3.0.0-rc.1`; `--selftest` and built-in regression successful.
- GUI: API tests cover system/interfaces/modules/preflight, loopback-only
  binding, Host validation, token checks, authorized/unauthorized start, and
  live job polling.
- MCP: existing protocol/stability suites plus the one-command private control
  plane, `capabilities`, and `preflight` tools.
- Linux: Docker build, 12 scan / 60 probe / 7 output / 5 generate modules,
  `http3:true`, `quic_transport:true`; runtime suite including GUI and MCP.
- Full Windows suite: selftest, i18n parity/coverage, schema and module
  validators (82 modules in this build), scan-request runtime, generate,
  control, MCP, MCP stability, TUI and GUI.
- Documentation: 159 Markdown files checked across the repository, 0 broken
  relative links; the English and Chinese manual chapters keep commands, flags,
  JSON and code blocks identical.

## Known limitations in this candidate

- GUI module parameters are visible but not yet editable per module; advanced
  `probe_args` must be supplied through the CLI or MCP in this candidate.
- The Results page lists jobs and opens their live view; it does not yet embed
  a record-by-record result browser.
- The UI preflight and start request are not bound by a server-side request
  hash yet; do not edit parameters between preflight and start.
- HTTP/3/QUIC is Linux-only in this candidate and depends on ngtcp2/GnuTLS.
- The control token remains optional for a local control plane; set
  `XTATE_CONTROL_TOKEN` when other local users may connect.
- The TUI is deprecated and will be removed once the GUI covers its remaining
  actions.
- There are no binary release assets in this candidate; build from source.

## Upgrade notes

- `--gui` / `--tui` no longer require a separately started `xtate
  --control-plane`; pass `--control-connect` only when attaching to a daemon.
- Scripts that parsed the old GUI's job-table page should use the JSON API
  (`/api/system`, `/api/interfaces`, `/api/modules`, `/api/preflight`,
  `/api/rpc`) instead.
- `--list-capabilities` exits after printing JSON and does not start a scan.
