# Xtate 3.1.0

Xtate 3.1.0 是稳定 3.0 系列之上的小版本。它把有状态探针的传输模型显式化，在
所有接口中暴露这些元数据，允许 `close-state` 关闭 QUIC 握手，并清理了 GUI
双语状态与容器网卡枚举问题。

命令行仍是专业互联网测量与研究的主要接口。GUI、MCP server 与 Agent Skill
都是同一个扫描引擎和控制面之上的额外客户端。

## 重点

- **探针传输成为一等属性。** 有状态探针声明 `ProbeTransport`（`TCP`、`QUIC`）
  和可选的 `ProbeCapability`（`stream-data`）。扫描模块声明所需传输与能力。
  `tcp-state` 接受 TCP 有状态探针；`quic-state` 接受 QUIC 有状态探针。
- **`close-state` 可用于 QUIC。** `close-state` 不发送应用层请求，握手完成后
  直接关闭传输。现在可被 `tcp-state`、`tls-state` 和 `quic-state` 接受；
  `http3-state` 仍是发送 HTTP/3 请求的 QUIC `stream-data` 探针。
- **模块元数据可发现。** `--list-scan` 与 `--list-probe` 输出类型、状态传输和
  能力；`--help-scan` 与 `--help-probe` 解释接受的探针形状。GUI 模块页展示
  传输和 `stream-data` 徽标；MCP `list_modules`/`describe_probe` 与 Agent Skill
  也描述相同字段。
- **兼容性一致执行。** CLI、interactive 模式、GUI 预检、MCP `validate_config`
  与 `start_scan` 使用同一个兼容性 helper。`quic-state + http-state`、
  `tcp-state + http3-state` 等非法组合在发包前被拒绝。
- **GUI 与容器细节。** 中文 System 页与英文 New scan 页不再混入另一种语言，
  动态状态文本也会本地化。GUI 网卡枚举过滤 libpcap 伪接口（`any`、`nflog`、
  `nfqueue`、`dbus-*` 等），消除容器中反复出现的 `No such device` 日志。

## 一分钟理解探针模型

| 概念 | 含义 |
|---|---|
| 探针类型 | 模块 ABI：`tcp`、`udp`、`state`。 |
| 状态传输 | 有状态探针可运行的线路上下文：`TCP`、`QUIC` 或两者。 |
| `stream-data` | 探针在握手后消费解密后的应用层字节流。 |

`http3-state` 是 `state` + `QUIC` + `stream-data`；`tls-state` 是 `state` +
`TCP`；`close-state` 是 `state` + `TCP/QUIC`，但没有 `stream-data`，因为它在
握手后立即停止。未来的探针可以同时声明两种传输；模型不假设所有有状态探针
都只支持 TCP。

## 兼容性与升级

- 从 3.0.0 升级不需要修改扫描配置、结果文件或 MCP 请求形状。
- 新接受 `quic-state + close-state`。`quic-state + http3-state` 仍是正常的
  HTTP/3 组合；`quic-state + http-state` 会被拒绝。
- 模块 JSON 新增 `state_transports`、`capabilities`、`required_state_transports`
  和 `required_capabilities`。消费者应忽略未知的可选字段。
- 人类可读的 `--list-scan`/`--list-probe` 在每个模块名后增加一行缩进元数据。
  按列解析名称的脚本应跳过或容忍随后的元数据行。
- `v3.0.0` tag 不变；3.1.0 是从它正常升级。

## 已知限制

- Windows 不提供 HTTP/3 或 QUIC 传输；能力报告会明确说明。
- 原始 L2 扫描需要支持的链路类型；Linux `loopback` 没有 Ethernet MAC，
  请使用 on-link 目标和真实抓包网卡。
- Linux banner/state 扫描期间需要按文档配置防火墙/RST 抑制规则。
- Linux 归档链接发行版动态库；Docker 镜像是自包含方案。Ubuntu 24.04
  运行库见 [Docker 构建](../docker-build.md)。
- 高速率取决于网卡、驱动和路径。GUI 为界面稳定性把速率输入限制在
  1–10,000；这不是引擎限制。CLI、MCP 与控制面接受正的小数速率和极高
  速率。
