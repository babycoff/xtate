# Xtate 2.43.0 发布说明

发布日期：2026-11-13。

## 重点

### TUI 控制面任务面板

Xtate 新增全屏终端任务面板，用于管理受管 job：

```bash
xtate --control-plane=/tmp/xtate-ctl.sock
xtate --tui --control-connect=/tmp/xtate-ctl.sock
```

TUI 是控制面客户端，不是第二条扫描路径。它列出 job，每两秒刷新，显示状态详情和
结果 manifest；支持确认后取消 job，也支持通过向导启动一个小范围已授权扫描（模块、
目标、端口、速率、超时、结果路径、可选接口，并要求精确输入 `YES`）。`j/k` 或方向键
选择，`r` 刷新，`s` 启动，`c` 取消，`Enter` 查看详情，`q` 退出并恢复终端。

stdin 或 stdout 不是终端时，`--tui` 只打印一次纯文本快照；冒烟测试和脚本使用这个
模式，Windows 命名管道和 Unix socket 都可用。

向导有意只覆盖 `start_scan` 的一部分：不支持 `include_file`、`probe_args`、
`scan_args`、zstd 和配额设置。这些请使用 MCP 或扫描请求文件。控制面仍只允许
本机连接，令牌对本地 socket/管道默认可选；共享机器上应设置
`XTATE_CONTROL_TOKEN`。

## 兼容性

- 不改变现有 CLI、MCP 或控制面请求。
- TUI 新增 `--tui` 参数；它要求 `--control-connect`，不会自行启动控制面。
- 版本字符串、`--version` 和 MCP `serverInfo.version` 均为 `2.43.0`。

## 已知限制

- TUI 只支持本机，不流式读取结果记录；它显示 manifest，分块内容请用扫描器 CLI、
  MCP resource 或自己的读取器读取。
- TUI 启动向导不覆盖完整 scan-request 字段（见上）。
- 主机有多个默认接口时，工作进程可能报 `multiple default interfaces detected`；
  先运行 `xtate --explain-target=<target>`，把输出接口粘贴到向导。
- 部分 VPN 适配器暴露 `RAW` 链路类型，Xtate 无法用于原始扫描；请先预检并选择
  支持的抓包接口。
- 取消是尽力而为；已经退出的工作进程会返回 `"cancelled": false`。
- 本地控制传输的令牌默认可选；如果其他本地用户可以访问 socket 或管道，请设置
  `XTATE_CONTROL_TOKEN`。
- MCP 仍然只支持静态 `targets`/`include_file`，未暴露 generate/流式输入。

## 升级说明

无需迁移。现有控制面、job、MCP 和结果文件保持兼容。TUI 的结果路径由控制面
进程解释，而不是 TUI 进程。
