# Xtate 2.44.2 发布说明

发布于 2026-11-13。

## 重点

### TUN/VPN 网卡现在使用正确的 RAW 链路类型

Xtate 以前把桩定义 `PCAP_DLT_RAW` 写成 `101`，这是 pcap 存盘文件里的
`LINKTYPE_RAW` 值；但 `pcap_datalink()` 返回的是 DLT 值，Npcap 对 TUN/VPN 网卡
返回的 `DLT_RAW` 是 `12`。这个不一致会让本来受支持的 RAW 网卡报错：

```text
unknown data link type: 12(RAW)
```

现在 `PCAP_DLT_RAW` 改为 `12`，并添加注释说明 DLT/LINKTYPE 两个命名空间的区别。
直接承载 IP 报文的网卡（包括 Clash/Meta 一类 fake-IP TUN 网卡）只要目标确实从该
网卡路由，就可以被选中并用于 raw 扫描。

### `--explain-target` 与扫描启动的链路类型预检

`--explain-target` 现在会打印所选网卡的链路类型，例如：

```text
Interface: \Device\NPF_{...}
Link type: RAW (12)
Note: RAW link sends IP packets without an Ethernet header; MAC and ARP are not used.
Check: OK
```

如果所选网卡不能承载 raw IP 报文，输出会给出警告和
`Check: FAIL (unsupported link type)`，命令以非零状态退出。扫描启动时应用同样的
规则，不再带着错误的抓包配置继续执行。

多默认网卡错误现在会提示诊断命令：

```text
multiple default interfaces detected (2); use -if to choose explicitly
hint: run "--explain-target=<target>" to see the route and link type
hint: run "--list-if" to list adapter IDs and addresses
```

Xtate 仍然不会在多个默认网卡之间静默选择。VPN/TUN 网卡也有默认路由时，请用
`-if` 明确选择物理网卡。

### 扫描启动时显示配置的速率

扫描开始前的横幅和 `--meta-filename` 文件现在都会输出实际速率，发包前即可看到
默认值或 `--rate` 设置：

```text
Scanner:    zbanner
Probe:      http
Generator:  blackrock
Interface:  3
Rate:       1000 packets/sec
IP version: v4
Scanning 1 targets
```

数值按配置原样显示；省略 `--rate` 时显示默认速率。

## 兼容性

- CLI、MCP 和控制面请求格式没有变化。
- 支持 RAW 的 TUN/VPN 网卡不再报 `unknown data link type: 12(RAW)`，而是可以
  正常使用。
- 不支持的链路类型会在预检/启动阶段以 `Check: FAIL` 或
  `cannot carry raw IP packets` 失败，而不是带着损坏的抓包路径启动。
- `--version`、版本字符串和 MCP `serverInfo.version` 报告 `2.44.2`。

## 验证

- Windows MSVC Release 构建成功；`--selftest` 与回归检查通过。
- 定向预检：`--explain-target=198.18.0.144` 显示 `RAW (12)` 和 `Check: OK`；
  `--explain-target=127.0.0.1` 显示 `EN10MB (1)`；经 Meta TUN 网卡的扫描返回
  预期 HTTP 响应。
- 启动横幅/元信息检查：`--rate=1500` 输出 `Rate:       1500 packets/sec`，元信息
  文件写入 `Rate: 1500 packets/sec`；MCP 测试会断言 worker 日志中的速率行。
- Windows/Linux 完整运行时套件均通过：i18n、schema/module 校验、scan-request、
  generate、控制面、MCP、MCP 稳定性、TUI 和 GUI。Windows 最终运行使用
  `bin\xtate.exe` 2.44.2（994304 字节）；Linux 使用 Docker 构建的
  `xtate-linux` 2.44.2 二进制。

schema/module 校验依赖 `jsonschema`，Windows 测试机已安装，Linux 运行时镜像中
没有，因此只在 Windows 上运行。

## 已知限制

- fake-IP 地址不是目标真实地址。请通过 DoH 解析真实地址，或让代理绕过目标，
  然后扫描真实地址。
- 某些 VPN 模式使用的链路类型不能承载 raw IP 报文。先用 `--explain-target`
  预检；必要时选择 Ethernet/Wi-Fi 网卡。
- TUN 网卡可能接受报文，但对端因策略丢弃流量；链路类型通过不代表应用一定响应。
- 多默认网卡规则不变：有多个默认路由时必须显式传 `-if`。
- `--check` 是 flag。要诊断指定目标，请用
  `--explain-target=<target> --check`；`--check=<target>` 会被当作 flag 解析。

## 升级说明

无需迁移。如果脚本把 `unknown data link type: 12(RAW)` 当作失败信号，请改用新的
预检结果。存在多个默认网卡时，继续显式传 `-if`。
