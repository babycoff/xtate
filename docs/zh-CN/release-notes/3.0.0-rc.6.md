# Xtate 3.0.0-rc.6

**候选版本，供手工试用，不是正式 3.0.0。**

本候选版本加固 MCP/Agent Skill 契约，并加入可复现的 Ubuntu 24.04 全功能
Docker 构建。

## MCP 与 Agent Skill

- `start_scan` 改为扁平 schema：扫描请求字段直接作为工具参数，旧的嵌套
  `{"arguments":{...}}` 会返回明确的 `unknown field: arguments`。
- 服务端拒绝未知请求字段；`global_args` 仅允许 23 个 GUI 安全选项，并校验
  类型、长度和范围。
- `preflight` 同时接受 JSON 数组和 GUI 的逗号分隔字符串形式的 `targets`、
  `ports`，两种写法结果一致。
- 工具参数超过 8 KiB 时返回
  `request too large; keep tool arguments under 8 KiB or use include_file`，
  不再误报授权/路径错误。
- `check` 现在真正执行 `--check` 并报告链路能力；Linux 防火墙仍通过独立的
  `xtate://docs/firewall` 资源查看。
- MCP 侧对控制面 token 做 JSON 转义，控制面负责解码；含 `"` 或 `\` 的
  token 可用。
- 新增 `tests/mcp/test_mcp_contract.py` 和 `tests/skill/test_skill_contract.py`，
  覆盖 schema、分帧、数组/字符串、未知字段、超长恢复、token 转义和 Agent
  Skill 示例。

## Ubuntu 24.04 全功能 Docker 构建

- 新增 `docker/ubuntu24-build/Dockerfile`，安装 Ubuntu 24.04 可用的全部可选
  依赖：OpenSSL、PCRE2、LibXml2、libbson/libmongoc、ngtcp2+GnuTLS、zstd、
  libpcap 与 Lua 5.3。
- 构建阶段断言 `http3`、`quic_transport`、`zstd`、`raw_sockets` 均为 true，
  且扫描模块为 12 个。
- `build.sh` 支持 `official`、`tuna`、`ustc`、`aliyun`、`huawei` APT 镜像和
  中国大陆基础镜像。
- 宿主机 GUI 访问需显式 `-e XTATE_GUI_ALLOW_REMOTE=1`，端口只发布到宿主机
  loopback；可用 `XTATE_GUI_PUBLIC_URL` 指定日志中打印的地址。
- 镜像设置 `XTATE_MCP_DOCS_DIR=/usr/local/share/xtate` 和
  `XTATE_STATE_DIR=/data`；挂载 `/data` 可保留结果。
- `docs/docker-build.md` 及中文翻译记录构建、镜像源、能力检查、宿主 GUI、
  原始扫描和 MCP。
- Linux 探测 libpcap soname 时不再把正常缺失的候选名记为警告。

## 兼容性

- 结果格式未变。
- 旧嵌套 `start_scan` 形式会被拒绝，客户端和 Agent Skill 需改为直接传字段。
- `--gui` 仍不自动打开浏览器，请手动打开打印的地址。
- TUI 仍为弃用状态，不属于 3.0。

## 验证

- Windows MSVC Release 构建与完整测试套件：通过。
- Linux Ubuntu 24.04 构建与完整测试套件：通过。
- Docker 镜像 `xtate:ubuntu24-full`：构建、selftest、能力断言、宿主 GUI
  页面/API、预检、`tcp-syn` 任务和 MCP stdio 握手均已测试。
- 独立 Agent Skill 契约复测：7/7 通过。
- 文档相对链接：0 个损坏。

## 已知限制

- 没有命名管道权限的沙箱无法验证 MCP 完整任务生命周期；该情况报告为
  blocked，不能算通过。
- `preflight` 不支持 `include_file`；路由检查用 `explain_target`，大目标集
  留给启动阶段。
- Docker 镜像不能打开宿主机文件选择器或结果查看器；使用挂载的 `/data`
  路径或 GUI 的 Results 页面。
- 正式 3.0.0 仍需用户试用并确认。
