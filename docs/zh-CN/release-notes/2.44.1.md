# Xtate 2.44.1 发布说明

发布于 2026-11-13。

## 重点

### 本机 TUI/GUI 一条命令启动

现在启动本机 TUI 或 GUI 不再需要第二个终端和单独的 `--control-plane` 进程：

```bash
xtate --tui
xtate --gui
```

省略 `--control-connect` 时，界面会在子进程中启动私有控制面，等待其接受 `ping`
后就绪，并在界面退出时停止它。私有子进程继承 UI 进程的
`XTATE_CONTROL_TOKEN`，因此设置 token 时仍然生效。

`--control-connect` 仍可用于连接已有控制面，适合任务需要比面板存活更久的场景：

```bash
xtate --control-plane=/tmp/xtate-ctl.sock
xtate --gui --control-connect=/tmp/xtate-ctl.sock
```

私有模式下控制面拥有 worker，并随 UI 一起停止；因此正在运行或排队的任务也会
停止。需要长时间运行的任务请使用 `--control-connect`。

自动启动复用同一个可执行文件和同一套控制面协议，TUI/GUI 进程本身并不内嵌扫描器。
Windows 上子进程被放入 kill-on-close job object；Linux 上设置
`PR_SET_PDEATHSIG`，并用 SIGTERM/SIGKILL 停止。就绪判断是 `ping` 重试循环，而不是
固定 sleep。

  token 继承以及何时应连接已有控制面。

## 兼容性

- 不改变现有 CLI、MCP 或控制面请求。
- `--tui`、`--gui` 不带 `--control-connect` 时，从原来打印
  `requires --control-connect` 错误改为启动私有控制面并成功运行。
- 版本字符串、`--version` 和 MCP `serverInfo.version` 均报告 `2.44.1`。

## 已知限制

- 私有模式下停止 TUI/GUI 会同时停止其控制面和任务。需要任务独立继续时请使用
  `--control-connect`。
- 私有控制面仅限本机：Windows 命名管道或用户临时目录下的 Unix domain socket，
  不监听 TCP。
- GUI 仍只监听环回且没有 TLS，不要暴露其端口。
- GUI 启动向导仍只覆盖 `start_scan` 的子集（不支持 `include_file`、
  `probe_args`/`scan_args`、zstd 或配额设置）。
- 取消是尽力而为；已经退出的 worker 会返回 `"cancelled": false`。
- 本机控制传输的 token 是可选的。其他本机用户可能访问 socket/pipe 时，请设置
  `XTATE_CONTROL_TOKEN`。
- MCP 仍只暴露静态 `targets`/`include_file`，未通过 MCP 暴露 generate/流式输入。

## 升级说明

无需迁移。现有控制面、job、MCP 和结果文件保持兼容。若脚本依赖
`--tui`/`--gui` 在没有 `--control-connect` 时失败，请显式传入端点以保留旧的双进程
行为。
