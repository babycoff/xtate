# Xtate 3.0.0-rc.1

这是发布候选版本，不是最终的 3.0.0。它用于实际试用和反馈；只有在真实使用中完成测试并修复报告的问题后，才会发布正式 3.0.0。

## 重点

### 以扫描为中心的浏览器控制台

旧的任务列表 GUI 已替换为面向任务的扫描控制台：

- **新建扫描** 是默认页面：目标范围、扫描方式、端口/探针、速率、超时、网卡、授权，以及服务端实时预检。
- **实时** 显示所选任务的阶段、已发包/目标数、心跳、耗时、退出码、日志路径和结果清单。
- **结果** 列出运行中和已完成的任务，点击进入实时视图。
- **网卡** 显示每个抓包设备的地址、网关、默认路由、链路类型以及是否支持原始 IP 抓包。
- **模块** 列出扫描引擎、探针、输出和生成模块及其参数名。
- **设置** 显示运行端点、模块数量和协议能力。

`xtate --gui` 现在会自动启动私有控制平面，在 `127.0.0.1:8787` 打开浏览器，并在 GUI 退出时停止私有 worker。需要连接已有守护进程时使用 `--control-connect`。

### 服务端预检

`POST /api/preflight` 会解析目标范围、解析路由、检查链路类型、校验扫描/探针组合、按扫描引擎协议过滤端口，并返回目标数/端口数/尝试次数及可操作的错误。只有预检通过、勾选授权且表单在预检后未修改时，**开始扫描** 才会启用。

### AI 与 MCP

- `xtate --mcp` 现在会自动启动私有控制平面，MCP 客户端只需一条命令。
- 新增 `capabilities` MCP 工具，报告平台、模块数量、原始套接字支持以及 HTTP/3/QUIC 可用性。
- 新增 `preflight` MCP 工具，在提交扫描请求前执行与 GUI 相同的目标范围/路由/链路/模块预检，不发送任何数据包。
- `xtate --list-capabilities` 以 JSON 输出能力文档，供代理和脚本读取。

### 协议能力报告

只有构建环境提供 ngtcp2 和 GnuTLS 时才编译 HTTP/3 与 QUIC 传输。Windows 构建会明确报告“不可用”，而不是静默省略模块；GUI 和 MCP 的能力输出会显示该限制。HTTP/1.1、HTTP/2、DNS/DoT/DoH 以及有状态 TCP/TLS 路径在两个平台均可用。

### 文档

`docs/manual/` 和 `docs/zh-CN/manual/` 下已包含结构化的中英文手册（各 10 章），并与现有参考章节配合使用。TUI 在 3.0 中已弃用：本候选版本保留 `--tui` 兼容，但它不是 3.0 支持的交互界面。

## 验证

- Windows 构建：MSVC Release，`xtate.exe` 1,039,360 字节，`--version` 为 `3.0.0-rc.1`；`--selftest` 和内置回归测试通过。
- GUI：API 测试覆盖系统/网卡/模块/预检、仅环回监听、Host 校验、令牌检查、授权/未授权启动以及任务实时轮询。
- MCP：现有协议/稳定性测试，加上新的单命令私有控制平面、`capabilities` 与 `preflight` 工具。
- Linux：Docker 构建，12 个扫描/60 个探针/7 个输出/5 个生成模块，`http3:true`、`quic_transport:true`；运行时测试包含 GUI 与 MCP。
- Windows 全量测试：selftest、i18n 中英文对齐/覆盖率、schema 与模块校验（本构建 82 个模块）、scan-request 运行时、generate、control、MCP、MCP 稳定性、TUI 与 GUI。
- 文档：检查仓库内 159 个 Markdown 文件，相对链接 0 处错误；中英文手册的命令、参数、JSON 与代码块保持一致。

## 本候选版本的已知限制

- GUI 可查看模块参数，但尚不能逐模块编辑；高级 `probe_args` 在此候选版本中仍需通过 CLI 或 MCP 提供。
- 结果页列出任务并打开实时视图；尚未内嵌逐条结果浏览器。
- UI 预检与启动请求尚未用服务端请求哈希绑定；预检后不要修改参数。
- 此候选版本的 HTTP/3/QUIC 仅支持 Linux，且依赖 ngtcp2/GnuTLS。
- 本地控制平面的控制令牌仍为可选；若本机其他用户可能连接，请设置 `XTATE_CONTROL_TOKEN`。
- TUI 已弃用；GUI 覆盖其余操作后将移除。
- 本候选版本不提供二进制发布资产，请从源码构建。

## 升级说明

- `--gui` / `--tui` 不再需要单独启动 `xtate --control-plane`；仅在连接已有守护进程时传 `--control-connect`。
- 解析旧 GUI 任务列表页面的脚本应改用 JSON API（`/api/system`、`/api/interfaces`、`/api/modules`、`/api/preflight`、`/api/rpc`）。
- `--list-capabilities` 输出 JSON 后退出，不会启动扫描。
