# Xtate 2.42.1

## 重点

- **面向 MCP 客户端的 Agent Skill。** `skills/xtate/` 提供经过审查的操作手册，
  教外部 agent 确认范围、预检路由、校验封闭扫描请求、启动有边界的 job，并读取
  manifest/分片。它是文档与策略，不是内嵌 agent，也不是权限边界。
- **全树审计加固。** 修复 DNS、NDP/ARP、HPACK、Lua TCP probe、ICMP quote 解析、
  pcap 输出、MongoDB 输出和结果存储中的内存安全与健壮性问题。
- **Windows UTF-8 路径。** CLI argv、include 文件、job/结果路径、输出文件和 MCP
  result_path 改用 Windows 宽字符 API，中文等非 ASCII 路径不再被当作 ANSI 解码。
- **Windows 路由查找。** adapter GUID 匹配现在正确处理 ANSI 格式的 adapter
  name；此前的宽字符转换会得到无效 GUID，导致 `explain_target`/`check` 和 MCP
  规划回退到默认网卡，而不是实际路由的 pcap 设备。
- **控制面加固。** 严格整数解析、唯一 request/result 名称、Windows Named Pipe
  按行分帧、Unix socket 私有权限、`mkstemp` 请求文件、SIGPIPE 处理和维护线程退出。
- **结果存储正确性。** manifest 与 index 路径会做 JSON 转义，Windows 反斜杠路径和
  带引号的路径都会生成合法 JSON。
- **JSON 契约对齐。** `dry_run` 明确真实默认值为 `false`，`rate` 接受 0-10000，
  `chunk_size` 至少为 1，`compression` 仅允许 `none`/`zstd`；参考 CLI 适配器支持
  `include_file`。

## 升级说明

- 省略 `dry_run` 一直是真实扫描。schema 现在如实标注；依赖旧
  `"default": true` 的工具在只想列目标时必须显式设置 `dry_run: true`。
- `timeout_sec` 必须是 1-86400 的整数；负数或非整数会被拒绝，而不是回绕。
- 旧版本写出的、反斜杠未转义的 manifest 可能需要用修复后的版本重新读取；新
  manifest 是合法 JSON。

## 验证

Windows 回归：selftest、i18n 一致/覆盖、MCP 协议与稳定性套件、generate/input、
控制面、scan-request 运行时、schema 与模块校验。Linux 回归：selftest、i18n、MCP
协议与稳定性、generate、控制面与 scan-request 运行时套件（Linux 测试镜像未安装
`jsonschema`，因此 schema 校验在 Windows 上执行）。审计还使用 clang ASan 与
libFuzzer 覆盖预处理、HPACK 和 DNS 解析器。

## 已知限制

- 本地客户端的控制面 token 仍可选；生产环境应设置 `XTATE_CONTROL_TOKEN`。创建
  Unix socket 时权限为 0600。
- MCP 审计日志写入 MCP 进程工作目录。
- 部分 VPN 网卡呈现 RAW link type，Xtate 无法用于原始扫描；请先用
  `explain_target` 预检并选择受支持的网卡或路由。
- 尚未实现从 `include_file` 做路由发现；只有在预检代表性目标后才传已验证的
  `interface`。
- MCP 仍未暴露 generate/流式输入；请使用静态 `targets` 或 `include_file`。
