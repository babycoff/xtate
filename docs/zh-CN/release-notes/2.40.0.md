# Xtate 2.40.0

新增 SSH KEX host key 指纹、DNSSEC 证据探测，以及按目标路由工作的网络诊断层。

## SSH

- 新增 `ssh-kex` state 探针，执行未认证的 `curve25519-sha256` 密钥交换并输出：

```text
ssh_host_key_type
ssh_host_key_bits
ssh_host_key_sha256
```

- 不进行用户认证、不建立 session、不执行命令。
- 已与本地 OpenSSH 兼容目标的 `ssh-keyscan`/`ssh-keygen` 指纹对照验证。

## DNS

- `dns --dnssec` 发送 EDNS0 OPT 且 DO=1，输出：

```text
dns_ad
dns_truncated
dns_rrsig_count
dns_dnskey_count
dns_ds_count
dns_nsec_count
dns_dnssec_present
```

- 这是 DNSSEC 部署证据探测，不做完整信任链验证。
- `--edns-size` 控制声明的 UDP 负载大小（默认 1232）。

## 网络诊断

- `--list-if` 每个网卡输出一行对齐表格：IPv4、MAC、默认网关和状态
  （`up`/`virtual`/`loopback`/`no-ipv4`）。
- `--explain-target <ip>` 只读输出目标/接口/源地址/网关；`--check` 做启动前预检。
- Windows 网关 MAC 先走 `SendARP`（系统邻居表），再回退 raw ARP。
- 目标路由：Windows 使用 `GetBestInterfaceEx` 与 IPv6 转发表；Linux 使用
  rtnetlink `RTM_GETROUTE`。
- `-if` 支持编号、GUID 或唯一描述子串。
- 存在多个默认接口且未指定 `-if` 时，启动会 fail-closed 报错，而不是猜测。

## 注意事项

- Windows IPv6 的路由/源地址/next-hop 已验证；IPv6 数据平面仍需实验目标。
- Windows 的 `--explain-target` 对 on-link 路由显示 `Gateway: unknown`。
- 输入/输出模块审查已列入计划，不在本版本内。
