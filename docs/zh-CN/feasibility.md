# P3 / P4 可行性评估

**中文** · [English](../feasibility.md)

这是工程可行性评估，不是实现承诺。前提是 2.30.0 架构：无状态
ZBanner/UDP、HLTCP 有状态 TCP、输出侧聚合。

## QUIC 探针与 HTTP/3 探索

**结论：研究项，高复杂度，是独立的传输层工程。**

QUIC 不是“UDP 上的 HTTP/2”。真正的 HTTP/3 探针需要：

- 合法的 QUIC Initial 报文，包含 header protection/加密；
- 集成 TLS 1.3，ALPN 为 `h3`；
- QUIC connection ID、packet number space、丢包检测和定时器；
- 如果要做真实请求，还需要 HTTP/3 control stream/QPACK。

选项：

1. 可选集成 `libngtcp2`/`libnghttp3`、`quiche` 或 `msquic`；
2. 只做 QUIC/Initial 能力探测，不做 HTTP/3 请求；
3. 不引入新依赖，明确列为非目标。

建议：先在扫描器热路径之外做 QUIC/HTTP/3 研究原型；不要加一个假的
“HTTP/3” UDP payload 探针。可选库必须保持可选，不能改变默认构建。

## P3 — 扫描控制

### 有限的目标相关探针选择

**结论：可行，中等复杂度，中等风险。**

目标：根据端口、banner、TLS 证据选择下一步探针，而不是对所有目标盲发所有
探针。

可行原因：

- 扫描器已经输出 classification、banner、TLS 字段；
- 选择逻辑可以放在报文热路径之外；
- 不需要 ZBanner 保存逐目标状态。

核心设计问题是决策放在哪里：

1. **外部控制器**：第一轮输出 NDJSON，控制器按探针生成第二轮目标文件。
   风险最低；不改扫描器 API；速度较慢。
2. **输出侧调度**：输出模块生成后续目标文件。仍然无扫描器状态；需要本地
   编排步骤。
3. **扫描器内选择**：需要逐目标决策状态和第二探针队列，与无状态设计冲突，
   不应作为第一版。

第一版验收：

- 输入/输出确定；
- 不保存无界 per-target 表；
- 有文档化的两轮 recipe；
- 测试证明只有证据匹配的目标会被选中。

### 自适应发包速率

**结论：可行，中高复杂度，高测量风险。**

目标：从低于固定 `--rate` 开始，观察丢包/超时/ICMP 错误后自动调整。

需要：

- 有界反馈窗口和控制环；
- 明确 min/max 速率和安全默认值；
- 区分本地拥塞、链路丢包和目标不响应；
- 确定性/手动回退（`--rate` 必须仍是权威）；
- lab 和真实网络验证。

风险：

- 反馈环可能震荡或放大丢包；
- 无状态扫描器无法归因每一个丢包；
- 结果会依赖速率，更难复现。

建议：作为现有 throttle 外围的可选控制器实现，不要放进 probe 回调。

### 跨层服务指纹

**结论：可行，数据模型复杂度高。**

组合 IP/TCP 选项、TLS 参数和应用层证据。扫描器只输出字段；归一化和分组放在
输出层。无状态实现不能维护逐目标指纹表。

### stateless → stateful 两阶段 handoff

**结论：可行，复杂度高。**

自然形式：ZBanner/端口证据选出少量候选，然后 HLTCP 对有状态 TLS/应用探针。
需要交接格式和调度器，并控制 TCB 成本。它与暂缓的 HLTCP slot 工作重叠。

## P4 — 模板与流量

### Xtate 原生 YAML 模板

**结论：可行，中高复杂度，接口面很大。**

要求：

- 小型 Xtate 原生 schema，不做 Nuclei 兼容；
- 模板编译到现有 probe/slot plan，而不是解释任意代码；
- 有界超时、载荷和输出字段；
- 明确失败语义；
- schema 版本和校验。

避免：嵌入通用语言、任意文件/网络访问、静默 Nuclei 回退。第一版只做只读
matcher/response schema 和少量编译动作。

### 扫描流量指纹随机化

**结论：可行，中等复杂度，研究与策略风险。**

选项：TCP option 顺序、IP ID 行为、源端口选择、TTL、HTTP header 顺序、
TLS 扩展顺序、GREASE。部分已在 stack/probe 设计中。

风险：

- 可能改变目标行为，影响测量有效性；
- 随机化降低可复现性；
- 可被滥用规避监测；
- 需要研究开关、确定性 seed 和清晰文档。

建议：只作为显式研究功能，不默认开启，且只在本地 lab 测试。

## 建议顺序

1. 完成 P2 协议覆盖和 JARM 实机对比。
2. 外部目标相关选择（P3，风险最低）。
3. 可选自适应速率控制器（P3）。
4. 只读 YAML 模板（P4）。
5. 流量随机化（P4，仅研究）。
6. HLTCP slot 决策确定后再做两阶段 handoff。

## 第一版非目标

- 扫描器内 per-target 选择状态；
- 无约束模板执行；
- 默认流量混淆；
- Nuclei 兼容；
- 功能或依赖不可用时的静默回退。
